## Original review

The extension has a coherent visual identity and a useful, restrained set of research-slide components. I would keep the typography, palette, heading rules, figure centering, and final-state handouts. The most valuable next work is to make component combinations reliable, improve navigation and small-screen reading, and make the examples easier to learn from.

This is a review, with no implementation changes or deployment. It identifies **11 defects**: one P1, nine P2s, and one P3. The design recommendations below are separate from those defects.

## Confirmed defects

### 1. P1 — A `./` image path can publish unrelated files

**Source:** [core.ts:275](/Users/adam/Code/altmejd-slides/_extensions/altmejd-slides/tools/publish/core.ts:275), consumed by [publish-cloudflare.ts:533](/Users/adam/Code/altmejd-slides/_extensions/altmejd-slides/tools/publish-cloudflare.ts:533).

With `![](./dot.svg)`, the staging planner takes the first path component, `.`, as a directory to copy wholesale. An actual `--stage-only` run with zero configured artifacts copied an otherwise unreferenced `private-handout.pdf` and `talk.qmd` into the public bundle. A normal publish would upload that bundle. This contradicts the documented promise that handout PDFs are never included implicitly.

Normalize harmless `.` components before planning, prohibit the output root from being a wholesale asset directory, and regression-test the staged file set with an unreferenced synthetic handout/source marker. A staged-file manifest would also make the upload scope reviewable. [Reproduced file manifest](/Users/adam/Code/altmejd-slides/output/review-2026-09-07/reproductions/staged-file-manifest.txt).

### 2. P2 — Hidden navigation can make a figure disappear

**Source:** [runtime.js:131](/Users/adam/Code/altmejd-slides/_extensions/altmejd-slides/resources/runtime.js:131), with unchecked element selection at lines 35–44 and boundary geometry at lines 70–85.

A stretched image followed by `.slide-nav.handout-only` disappears in live mode. The runtime measures the hidden navigation's zero rectangle and sets the figure's maximum height to `0px`. The same image measured 748 layout pixels high in handout mode. `.slide-nav.live-only` has the reverse problem in handouts.

Select only visible bottom boxes and clear their reserve variables when hidden. Test both delivery modes with figures, navigation, and notes together. [Live: missing figure](/Users/adam/Code/altmejd-slides/output/review-2026-09-07/reproductions/hidden-nav.png); [handout: visible figure](/Users/adam/Code/altmejd-slides/output/review-2026-09-07/reproductions/hidden-nav-handout.png).

### 3. P2 — `.live-only` speaker notes still appear in handouts

**Source:** [theme.scss:1439](/Users/adam/Code/altmejd-slides/_extensions/altmejd-slides/theme.scss:1439).

`::: {.notes .live-only}` becomes an `aside.notes.live-only`, but the handout note's more specific `display: block !important` defeats the delivery-mode hiding rule. The note text remains visible under `?handout=true` and therefore enters the handout PDF.

Make delivery-mode exclusion win, and fix the runtime visibility handling above at the same time so correctly hidden notes do not become zero-height geometry boundaries. [Reproduction](/Users/adam/Code/altmejd-slides/output/review-2026-09-07/reproductions/hidden-speaker-note-handout.png).

Separately, Quarto strips additional classes from native `.aside` blocks during transformation. An aside with `.handout-only` also needs either a documented supported wrapper pattern or early class preservation. That upstream interaction is not counted as a separate extension defect here.

### 4. P2 — Adding an aside overrides `.nostretch`

**Source:** [altmejd-slides.lua:556](/Users/adam/Code/altmejd-slides/_extensions/altmejd-slides/altmejd-slides.lua:556).

`![](estimate.svg){.nostretch width="300"}` stays 300 pixels wide on its own. Add an ordinary aside and the filter inserts `.r-stretch`, increasing it to 1470 pixels in the reproduction. This can unexpectedly enlarge a logo, portrait, or deliberately small diagram when the author adds a source note.

Honor `.nostretch` and native Quarto sizing exclusions before applying automatic stretching or `layout-fill`. [Without aside](/Users/adam/Code/altmejd-slides/output/review-2026-09-07/reproductions/nostretch-alone.png); [with aside](/Users/adam/Code/altmejd-slides/output/review-2026-09-07/reproductions/nostretch-aside.png).

### 5. P2 — Separate internal-link paragraphs overlap

**Source:** [altmejd-slides.lua:648](/Users/adam/Code/altmejd-slides/_extensions/altmejd-slides/altmejd-slides.lua:648), [theme.scss:1068](/Users/adam/Code/altmejd-slides/_extensions/altmejd-slides/theme.scss:1068).

Two paragraphs, `[Data](#data)` and `[Methods](#methods)`, become two independent absolute `.slide-nav` rows. Both dock to exactly the same bottom-right point; the larger Methods chip covers Data. An explicit navigation row plus an automatically promoted paragraph can do the same.

Coalesce generated links into one row per slide, or make docking explicitly opt-in and retain ordinary link paragraphs in flow. The runtime currently measures only the first row, so fixing just CSS stacking is insufficient. [Reproduction](/Users/adam/Code/altmejd-slides/output/review-2026-09-07/reproductions/multiple-nav.png).

### 6. P2 — Keyboard focus enters invisible slides

**Source:** [theme.scss:1300](/Users/adam/Code/altmejd-slides/_extensions/altmejd-slides/theme.scss:1300); similar unconditional display overrides exist for the title, statement, and divider slide layouts.

While the visible slide was `robustness-summary`, Tab focused links in `design-diagnostics`, `effects-over-time`, and the closing slide. For the distant diagnostics slide, Reveal had set inline `display: none`, but the theme's `display: flex !important` kept the links focusable inside an opacity-zero section. `aria-hidden="true"` does not remove them from keyboard navigation. Nearby ordinary Reveal slides can also remain focusable: this is both an inherited focus-management gap and an extension override that expands it.

Make inactive slides inert or explicitly exclude their controls from tab order, and preserve Reveal's hiding decisions when applying custom display layouts. Verify forward/backward Tab, Enter activation, slide changes, and overview mode. [Recorded focus sequence](/Users/adam/Code/altmejd-slides/output/review-2026-09-07/interactions.json). This affects meaningful keyboard focus order as described by [W3C](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html).

### 7. P2 — Dark slides do not have complete component color pairs

**Source:** [theme.scss:755](/Users/adam/Code/altmejd-slides/_extensions/altmejd-slides/theme.scss:755), [dark-slide overrides:677](/Users/adam/Code/altmejd-slides/_extensions/altmejd-slides/theme.scss:677).

On `.dark-bg` with `background-color="#0f172a"`, a plain `.stat` uses the same `#0f172a` and disappears completely. The light blockquote surface receives white links, approximately 2.02:1 contrast. Its bold emphasis is also about 2.04:1. Emphasis chips and table notes have other weak combinations. Plain table cells correctly inherit white and are not broken.

Define readable foreground/background pairs for every supported component on dark slides. Keep dark ink on light quote/card surfaces, and light ink directly on dark surfaces. Test the component combinations, not just dark body text and one callout. Text contrast should meet the appropriate 4.5:1 or large-text 3:1 threshold; see [W3C contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

![Dark-slide reproduction: the number above applications is invisible, while quote links and source text lose contrast.](/Users/adam/Code/altmejd-slides/output/review-2026-09-07/reproductions/dark-components.png)

The menu needs a related color pass: its button stays burgundy on a dark slide, while the open menu's toolbar icons remain white on the new near-white surface. The toolbar text labels remain readable. [Menu screenshot](/Users/adam/Code/altmejd-slides/output/review-2026-09-07/menu-open.png).

### 8. P2 — Phone footer text overlaps the slide counter

**Source:** [theme.scss:515](/Users/adam/Code/altmejd-slides/_extensions/altmejd-slides/theme.scss:515).

At 375 pixels wide, the showcase footer text ends at x=302.4 while the counter starts at x=284.5: nearly 18 pixels of overlap. The footer reserves right padding, but its unwrapped child paragraph overflows that content box. Clipping and ellipsis are applied to the outer full-width footer, so they do not protect the counter.

Constrain and ellipsize the actual text-bearing element, or hide secondary footer text below a small-screen breakpoint. Add a viewport-level chrome collision check; the current showcase audit concentrates on slide-internal content. [Phone screenshot](/Users/adam/Code/altmejd-slides/output/review-2026-09-07/mobile-footer-collision.png).

### 9. P2 — Nested deck inputs cannot be staged for publishing

**Source:** [publish-cloudflare.ts:979](/Users/adam/Code/altmejd-slides/_extensions/altmejd-slides/tools/publish-cloudflare.ts:979).

In a project with `output-dir: _site`, `--input talks/talk.qmd --stage-only` renders `_site/talks/talk.html`, then fails with `render did not produce _site/talk.html`. The publisher discards the source's relative directory when resolving the output file.

Resolve the actual output relative to the Quarto project and use the HTML's parent directory for its asset references. Include a nested-project integration case, including shared `../site_libs` resources. This was reproduced with the unmodified publisher and actual Quarto rendering, not just inferred from source.

### 10. P2 — PDF caching misses changes inside embedded local HTML

**Source:** [render_revealjs_pdfs.py:447](/Users/adam/Code/altmejd-slides/tools/render_revealjs_pdfs.py:447).

For a slide embedding `figure.html` in an iframe, where that HTML loads `plot.svg` outside the automatically collected `NAME_files` directory, changing only the plot leaves the PDF cache digest unchanged. The dependency scan recurses into CSS but not HTML, so an existing PDF can retain old visible results.

Either follow local HTML/SVG dependencies, or disable caching when the dependency set is incomplete. Test with a changed plot marker. This finding is verified through the dependency collector and digest helper; a full before/after PDF capture of this edge case was not run.

### 11. P3 — Empty `srcset` entries crash PDF discovery

**Source:** [render_revealjs_pdfs.py:194](/Users/adam/Code/altmejd-slides/tools/render_revealjs_pdfs.py:194).

`parse_srcset('plot.svg 1x,')` raises an uncaught `IndexError`. Ignore empty candidates before indexing their first token. This is input robustness, below the visual and workflow issues above.

## Design and authoring recommendations

### Make navigation quiet but usable

The navigation chips are too small for their purpose. At 1280 × 720 the text is 10.8 screen pixels and targets are only 20.8 pixels high. On a 375-pixel phone they fall to 3.2-pixel text and 6.1-pixel target height. Tablet portrait also leaves 6.5-pixel chip text.

Keep the restrained appearance, but establish a screen-space size floor or put reading controls outside the scaled slide canvas. Increase the hit area without making the decoration louder. For web controls, use the [WCAG 2.2 target-size guidance](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), including its spacing exceptions, rather than assuming that a small visible chip is sufficiently operable. Give the menu button an accessible name; the current anchor has no text, title, or `aria-label`.

### Treat reading on a phone as a separate use case

Phone body text is about 8.4 screen pixels; table text is about 6.9. The deck occupies a small 16:9 strip in a tall viewport. The 700-pixel breakpoint stacks figure panels inside that same scaled canvas, further reducing individual plots. It prevents overflow but does not create a usable reading experience.

Preserve the presentation canvas for presenting. Offer a clearly reachable reading/download route, with substantive text and figure descriptions at readable sizes. Do not simply re-enable Reveal scroll view: the runtime deliberately disables it because of Quarto's vertical section stacks. A reading mode needs its own validation. A landscape/fullscreen hint can help in the meantime but is not equivalent to a readable page.

### Make the current section easier to recognize

The burgundy agenda slides are visually consistent, but the active section differs mostly by white versus cream while both active and inactive labels use weight 560. A stronger active weight plus a small marker would be clearer. An alternative is a large current-section title above a quieter roadmap.

Consider omitting Appendix from main-talk agendas while retaining it in the menu. Backup material appears in every roadmap even though it is intentionally excluded from the slide count. This is an authoring choice, not a counting bug.

### Demonstrate a stronger evidence hierarchy

Several showcase tables and callout slides occupy only the upper portion of the canvas, while notes and action links are tiny at the bottom. The spare space is useful, but it could support a larger key result or a one-sentence interpretation rather than more decoration.

Provide copyable recipes built around a claim, evidence, and qualification. For example, replace the example heading “Main effect after two terms” with “Evening access adds 0.18 completed courses”, keep the interval legible on the figure, and place the local-effect qualification close to that result. Use the statement slide for a deliberate summary or pause. The current palette and figure build-up already support this without adding animation or a new component system.

### Separate the talk demonstration from authoring explanations

The showcase is a good regression fixture, but repeatedly explaining `.stat-row`, `.aside`, `.table-note`, and other syntax inside the audience-facing slide competes with the synthetic research narrative. Keep a clean demonstration mode and move those explanations into speaker notes, a companion recipe page, or an explicitly technical component gallery.

The starter should expose only the settings most authors need initially, with the full palette available as a copyable reference. Repeating every default encourages configuration drift and makes a new deck look more complicated than the extension actually is. Add an explicit escape hatch for automatic two-image panel conversion so intentionally unequal columns remain easy to author.

### Complete the reader and export workflow

- Preserve the original hyperlink around generated QR images. A person already reading the HTML should be able to click the paper resource without scanning a second screen. The current QR transformation deliberately emits a bare image; this is an enhancement, not a broken documented promise.
- Give installed starter decks a documented, pinned, one-command PDF path. The repository renderer works, but `.quartoignore` excludes it and its dependency lockfile; the starter Makefile has no PDF target. Repository-specific instructions are not a complete workflow for a newly installed deck.
- Review PDF footer and counter sizing at fit-to-page scale. The default doubled capture viewport preserves slide-content proportions while viewport-level chrome becomes much smaller; the sampled PDFs have especially tiny page labels. Keep metadata quiet but readable and consistent across capture resolutions.
- Expose existing overflow checks as an optional author preflight. A clear report of clipped notes/code, broken anchors, and missing alt descriptions would be more useful than requiring authors to notice the current dashed overflow border. Avoid silently shrinking content to make a test pass.

## Recommended order

1. Fix publication scope first, with a staging regression.
2. Fix component interactions together: visibility-aware layout, delivery gates, `.nostretch`, one navigation row, hidden-slide focus, and dark color pairs. Add focused cases to the existing fixtures.
3. Fix phone chrome and establish usable navigation sizes; decide on the supported small-screen reading route.
4. Improve the showcase recipes, agenda emphasis, QR interaction, and installed-deck PDF path.

This does not require replacing Quarto/Reveal or adding a UI framework. The architecture and visual identity are good foundations; the weaknesses are mostly a few automatic transformations and CSS rules that do not compose as authors would expect.
